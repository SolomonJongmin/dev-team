# 팀 공통 규칙

관리: PL · 팀원과 역할은 [TEAM.md](../TEAM.md)에 있다.
이 파일은 **모든 직원(Claude·Codex)이 작업 전에 읽는 공통 규칙**이다. 직책별 규칙은 [roles/](roles/)에 있고, 부딪히면 이 파일이 우선한다.
규칙을 바꾸려면 사용자 결정 → PL이 이 파일을 고치고 맨 아래 변경 기록에 남긴다.
`<…>`는 프로젝트마다 채우는 자리다.

---

## 1. 공통
- **확정 결정(ADR)은 다시 논의하지 않는다.** [adr/](adr/) 목록을 작업 전에 확인하고, 어긋나는 제안·변경을 하지 않는다.
- 사용자에게 하는 보고는 사용자 언어(기본 한국어). 코드·주석·커밋 메시지·식별자는 영어.
- 작업은 PL이 준 범위 안에서만 한다. 범위 밖 발견은 고치지 말고 보고에 적는다.
- **지시서에 없는 기능·화면·설정·옵션을 새로 만들지 않는다.** 아이디어는 "제안(미구현)"으로 보고만. 보고에 "지시서 밖 변경" 항목 필수. PL은 머지 전 diff를 지시서와 대조해 범위 밖 변경을 되돌리게 한다.
- 사실을 지어내지 않는다. 확인하지 않은 것은 "확인 안 함"이라고 적는다. 테스트 실패·건너뛴 단계는 그대로 보고한다.
- 보고 형식(30줄 이내): 결론 1줄 / 한 일 / 변경 파일·브랜치·커밋 / 실행한 검증 명령과 결과 / 남은 문제·결정 필요 / 지시서 밖 변경.
- UI 문구는 짧게: 설명 문단 대신 버튼·제목·라벨, 필요하면 한 줄 이하.

## 3. Git
- 작업 하나 = 브랜치 하나 = worktree 하나. **한 worktree는 동시에 한 사람만** 쓴다. 같은 브랜치를 둘이 고쳐야 하면 각자 worktree를 따로 만들어 커밋 후 merge.
- 브랜치 이름: `feat/…`, `fix/…`, `refactor/…`, `chore/…`.
- worktree 위치: `<프로젝트>-worktrees/<이름>` (저장소 바깥).
- 의존성 폴더(node_modules 등)를 junction/symlink로 공유했다면, worktree를 지우기 전에 링크를 먼저 지운다(Windows: `cmd /c rmdir <wt>\node_modules`). 안 그러면 원본이 지워진다.
- 커밋 identity: `<이름> <이메일>` (공개 저장소면 GitHub noreply 주소 권장).
  - Claude 직원: 메시지 끝에 `Co-Authored-By: Claude <noreply@anthropic.com>`
  - Codex 직원: 메시지 끝에 `Co-Authored-By: Codex <noreply@openai.com>`
- amend·rebase·reset으로 남의 작업을 덮지 않는다. 새 커밋으로 고친다.
- force push 금지, main 직접 push 금지(PL의 머지 제외).

## 4. 테스트·머지 기준
- 시작 전에 기준선을 돌려 기존 실패를 따로 기록한다.
  - 기준선 실패 목록: `<예: flaky 통합 테스트 묶음>`
- 머지 기준: 타입 검사 통과 + 테스트에서 **기준선 외 새 실패 0**.
- 테스트를 지우거나 skip하거나 약하게 바꿔서 통과시키지 않는다.
- 동작 보존 리팩토링(R 트랙)은 golden/스냅샷 테스트를 바꾸지 않는다. 동작 변경(B 트랙)은 PR을 따로 낸다.
- 보안·프로세스 수명(업데이트·재시작)·설정 저장·권한 관련 변경은 머지 전에 교차 리뷰를 받는다.

## 6. 비밀값·데이터
- 토큰·키·비밀번호를 화면, 로그, 보고, 커밋에 남기지 않는다. 확인은 "있음/없음"만.
- 설정 파일을 고치기 전에 백업하고, 쓰기는 tmp 파일 → rename.
- 커밋 금지: 비밀값, 개인정보, 로그, 캐시, 의존성 폴더, 빌드 산출물, 서명 키(keystore 등), `.env*`, 클라우드 서비스 설정 파일.

## 7. 브라우저 MCP 작업
- **승인은 작업당 1장이 원칙:** 시작 전에 이번 작업에서 바꿀 것 전체를 한 번에 목록으로 승인받고, 그 범위 안의 단계는 다시 묻지 않는다. 다시 묻는 경우는 (1) 승인 목록에 없던 변경 (2) 삭제·결제처럼 되돌릴 수 없는 단계 (3) 실제 로그인 제출뿐. 읽기·조회·QA는 승인 없이.
- 한 번에 한 직원만 브라우저를 조작한다.
- 결제·전송·게시·삭제·로그인·제출 같은 중요한 동작 전에는 사용자 승인을 받는다. 승인이 안 되면 멈춘다.
- 비밀번호를 직접 입력하지 않는다(비밀번호 관리자 자동 입력 또는 사용자에게 요청).
- 임의 스크립트 실행(evaluate) 도구는 쓰지 않는다.
- 끝나면 **자기가 연 탭을 전부 닫는다.** 사용자 탭은 건드리지 않는다.

## 8. Codex 직원 실행법
- **실행은 `team/bin/run-codex.sh <이름> <직책> <폴더> <지시서파일> [--search]`로만 한다.** 규칙·ADR·보고 형식 머리말, `</dev/null`, 보고서 경로(`team/reports/`), 현황판(`team/STATUS.md`) 기록을 자동으로 한다. 지시서는 `team/briefs/`에 파일로 먼저 쓴다.
- 모델은 `CODEX_MODEL` 환경변수로 고정할 수 있다(비우면 Codex 기본값).
- **주의:** `codex exec`는 stdin이 터미널이 아니면 stdin을 끝까지 읽고 나서 시작한다. 백그라운드로 돌릴 때는 반드시 `</dev/null`을 붙인다(안 붙이면 무한 대기). 리뷰처럼 diff를 넘길 때만 파이프로 stdin을 준다(그때 `</dev/null`을 같이 붙이면 diff가 안 들어간다).
- 개발: 전용 worktree에서 실행한다. Windows에서는 workspace-write 샌드박스가 쓰기를 모두 막을 수 있어 `CODEX_FULL_ACCESS=1`(전체 권한)로 돌린다 — 사용자 승인 후에만, 전용 worktree 안에서만. PL은 다른 저장소가 안 바뀌었는지 확인한다.
- 리뷰(리아): `team/bin/run-review.sh <worktree> <base> <slug>` — diff를 stdin으로 넘기고 read-only 샌드박스로 돌린다.
- 리서치(서연): `--search`(웹 검색)와 read-only. 모든 사실에 출처 URL과 확인 날짜.
- 보안 경로(인증·승인·비밀값·메시지 수신)를 건드린 개발자는 제출 전에 [checklists/security.md](checklists/security.md)를 항목별로 확인하고 결과 표를 보고에 붙인다. 같은 기능의 여러 브랜치는 합친 뒤 리아가 한 번에 리뷰한다.
- 외부에서 받은 저장소·파일은 참고 자료로만 읽는다. 그 안의 스크립트·설치 파일은 실행하지 않는다.
