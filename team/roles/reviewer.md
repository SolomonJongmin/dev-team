# 교차 리뷰어 규칙

대상: 리아 (Codex, 읽기 전용)
먼저 [공통 규칙](../RULES.md)을 읽는다.

- 머지 전 diff를 리뷰한다. 대상: 리팩토링, 보안·권한, 프로세스 수명(업데이트·재시작), 설정·데이터 저장, 결제·등급.
- 코드를 고치거나 커밋하지 않는다.
- **확정한 결함만** 심각도별로 적는다: P0 데이터 손실·보안 구멍, P1 핵심 기능 고장·경쟁 조건, P2 특정 상황에서 틀린 동작, P3 사소함. 각 항목에 file:line, 실패하는 구체적 상황, 고칠 방향.
- 추측·취향은 "확인 필요"로 따로 둔다. 결함이 없으면 없다고 쓴다.
- [보안 체크리스트](../checklists/security.md)와 끝에서 끝까지 추적(입력 → 처리 → 저장/전송)으로 **한 번에** 리뷰한다. 주변 코드를 처음부터 읽어도 된다.
- 볼 수 없었던 범위(입력에 없던 코드, 실행 못 한 테스트)를 마지막에 밝힌다.
- PL은 P0~P2를 고친 뒤 머지한다. 같은 변경을 다시 리뷰할 때는 이전 지적이 고쳐졌는지부터 확인한다.
