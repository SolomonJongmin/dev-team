# 개발자 규칙

대상: 도윤·서진·유진·준·한별·다인 (담당 영역은 [TEAM.md](../../TEAM.md))
먼저 [공통 규칙](../RULES.md)을 읽는다. 부딪히면 공통 규칙이 우선한다.

## 담당 영역
- 담당 밖 파일은 고치지 않는다. 꼭 필요하면 이유와 바꿀 내용을 보고하고 PL 결정을 기다린다.
- 공용 파일(패키지 매니페스트, lockfile, 컴파일 설정, 설치 프로그램, 릴리스 스크립트, 공용 메시지 계약)은 PL과 조율한 뒤에만 바꾼다.

## 작업 순서
1. 지시를 읽고 범위·완료 기준을 확인한다. 이미 된 작업은 다시 하지 않는다(`git log`, 브랜치 확인).
2. 기준선 테스트를 돌려 기존 실패를 기록한다.
3. 작게 고치고, 고친 동작마다 회귀 테스트를 붙인다. 버그 수정은 "수정 전에 실패하는 테스트"를 먼저 만든다.
4. 체크포인트마다 작은 단위로 커밋한다.
5. 끝나면 테스트·타입 검사·빌드를 다시 돌리고 보고한다.

## 코드
- 주변 코드처럼 쓴다: 이름 짓는 방식, 주석 밀도, 관용구를 맞춘다.
- 요청받지 않은 리팩토링·포맷 변경·의존성 추가를 하지 않는다.
- 사용자에게 보이는 문구는 기존 화면 톤을 따르고 짧게.
- 실패를 조용히 삼키지 않는다. 사용자에게 보이는 오류 문구는 무엇을 하면 되는지 알려준다.

## 영역별 확인 (예시 — 프로젝트에 맞게 채운다)
- **서버/앱:** `<타입 검사 명령>`, `<테스트 명령>`. 동작 보존 리팩토링이면 golden 테스트 불변.
- **관리자 도구:** 테스트 + 빌드. 빌드 산출물은 커밋하지 않는다. main 자동 배포라면 PL 리뷰 전 머지 금지. DB SQL은 작성만, 실행은 PL.
- **웹사이트:** HTML·구조화 데이터 파싱 확인, sitemap·robots와 실제 파일 일치, 링크 경로 존재 확인. 수치(사용자 수·평점·가격)를 지어내지 않는다.
- **모바일:** 서명 키·서비스 설정 파일·`.env*` 커밋 금지. 테스트는 에뮬레이터로.

## 하지 않는 것
- push, PR, 머지, 배포, 릴리스, 운영 데이터 변경.
- CI 정책에 어긋나는 워크플로 파일 추가.
- 테스트 삭제·skip·약화.
